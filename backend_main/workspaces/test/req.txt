So here we have a tool called Coaider which has a major features like 
Using the tech stack FASTAPI Python backend and Vite React
1. Command Line AI Coding assistant that enables pair programming using local LLM's with complete privacy, with smart context management aider maps all your uploaded files in repository to a map reduce approach to understand the code architecture across large codebases, also facilitates multi file editing can analyze dependencies and make coordinated updates across several files based on a single instruction. 
What we have done : WE have added a PTY terminal so user can interact with aider using OLLAMA chat, also the console has two modes one is terminal mode where user can add files, check the map repo, check token usage, on top of console modes we have chat modes like ask, code, architect modes, after selecting a chat mode user can select a LLM from a list of models based on their task and context required, so after that user can start chatting either of modes like just for QnA on attached files used /ask mode, for performing writing or updating or delete existing or refactoring existing code used /code mode, for planning any task on attached file we have /architect mode, these all modes can be viewed internally from terminal view mode, other side we have supervised mode where we dont even select chat mode , just select the llm model, attach the required files to be processed & give prompt to be done by LLM, that all, it take care but it needs your yes/no when it is a simple creating or modifying files to have data strength.
After that on top of all the things we have frontend where usually aider (open-source) it provides only a terminal application, here we have built a frontend view with both terminal and supervised modes, in terminal mode the frontend receives ansi color, real time movements in terminal, scroll back, interaction with aider using PTY. But in supervised mode it does attach files, Enter task,Create isolated Aider session,Monitor Aider output, Identify current phase, Show progress, Handle questions, Show changes,Review diffs (it is auto commit - undo if wanted).
Our frontend detects which file Aider is currently modifying.
shows build the per-file editing status. shows extract/display Aider's actual response text?
provides cross QnA with Aider asks an interactive question, at last the user answer those questions directly from your UI, by not even touching in terminal from both supervised mode, also user stop/cancel a running operation, system know when Aider has completed a task, keep in mind is this takes time because of multiple parallel request to LLM Server and file changes and majorly thinking of the LLM to map the large codefiles into a mindmap.

Usually for aider they have given multiple commands, to be typed in terminal console, but here we have provided a command palette where user can click that command on UI, so the frontend itself passes it to backend and does the needful, like clear, drop, tokens, etc.

We also provided version history and Undo for files which were modified in the session using git.

We have Code Canvas where user can select the file and check their version diffs in historic versions.

Also apart from pair programming module we have included Static Code analysis using pylint and semgrep it shows up the errors, warnings, refactors, conventions, style categories and provide a singe button call fix with AI, from that time the LLM take cares of that file/ folder, after that itgives us a proposed modification using diffs takes user approval and writes in original file.

Also apart from the above two we have modularization tool that uses LLM where we can give a big file/ folder having multiple files by attaching to the session, there LLM has set with arbitrary prompts to do modularization, if not in the case user can rewrite or refactor the prompt to their usecase.

Also apart from those above, we have test case generation where it gives us a file in appropriate related langage in the codebase naming test_codebase_xx.lang like many tests using llm and a test module, after that we have a separate feature called FIX_THE_STITCH, where we can attach a test_case.lang file and other side we can attach a folder / file(s) so it check and edits the folder/file(s) so it is satisfying the test cases.

Also apart from that we have SCA with SonarQube webAPI for folder/file(s)
