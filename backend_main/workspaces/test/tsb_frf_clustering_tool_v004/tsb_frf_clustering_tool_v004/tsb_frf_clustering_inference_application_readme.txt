[1] Introduction
=================================================================================================================
    - This readme file describes the procedure to use the below package:
        - FRF Clustering Inference Application

    - FRF Clustering Inference Application used for Inference using the Time Series K-Means clustering algorithm on the Frequency Response Functions of MA and VCM data.

        - This tool outputs consolidated inference summary for the dataset, bode plot visualizations, cluster plots, drive-wise cluster assignment CSVs.

[3] Execution of FRF Clustering Inference Application
=================================================================================================================
    - FRF Clustering Inference Application to be executed using the following steps:

        - Copy the "input_inference_config.cfg" generated inside "frf_clustering_analysis_<timestamp>" after the completion of the execution of "tsb_frf_clustering_training_application" for the specified training configuration.

        - Paste the copied "input_inference_config.cfg" in "frf_inference_config" directory of "tsb_frf_clustering_inference_application".

        - Set "root_dir" in "input_inference_config.cfg" to the training output directory path generated by "tsb_frf_clustering_training_application" (this directory contains the trained models and feature config). All relative paths in the config file will be constructed based on this "root_dir".

        - By default, "root_dir" is automatically pre-filled with the training output directory path from the latest training execution. Users can modify it if they want to use a different training output directory.

        - Set "output_path" in input_inference_config.cfg to the desired location where the inference output directory should be created and populated.

        - The ".txt" file created from the "frf_data_list_create.py" file should be provided to the desired config file.

        - The "input_inference_config.cfg" is generated as a result of the "tsb_frf_clustering_training_application". It and only it, is to be used for the execution of the "tsb_frf_clustering_inference_application".

        - To use the "input_inference_config.cfg", modify only the "INFERENCE_APPLICATION_REQUIRED_PARAMETER" in the "input_inference_config.cfg".

        - Once the "input_inference_config.cfg" is configured, run the below command:
          (frf_hdd) $ python frf_inference_application.py --config frf_inference_config/input_inference_config.cfg

            - Description of the above command:
              python frf_inference_application.py --config <Arg1>
              Arg1: Path to the "input_inference_config.cfg" inside the frf_inference_config subdirectory

       - The output directory containing the inference results will be created inside the "output_path" specified in the config file, as described below:

            Outputs:
            A successful run of the tool generates the following directory structures based on the configuration specified in the config file:

            **Abbreviations**
            {ts}      - timestamp
            {H}       - head name. For combined heads: "HD_<concatenated 2-digit codes>" when no
                                keyword is used (e.g. HD0+HD1 -> HD_0001), or "<shortened keyword(s)>[_<extra codes>]"
                                when "heads" uses a keyword (all_heads/odd_number_heads/even_number_heads/
                                outer_heads/inner_heads -> "_heads" shortened to "_hds", e.g. "all_hds",
                                "outer_hds_inner_hds", "odd_number_hds_0A")
            {seg}     - segment name, e.g. 200.00_400.00Hz
            {grp}     - baseline group: phase_lead / phase_lag / no_resonance, or a combined label
                        joining several with "_" (e.g. phase_lead_no_resonance) per baseline_data_filtering
            {klabel}  - the trained model's directory name
            {lbl}     - the compact tag embedded in every LEAF FILENAME inside a {klabel}
                        - not merged : {klabel} with 'stage1_k_'->'s1_k', 'stage2_k_'->'s2_k', 'k_'->'k'
                                        e.g. "k_4" -> "k4" ; "stage1_k_2_stage2_k_3" -> "s1_k2_s2_k3"
                        - merged     : always "origk{origk}_k{k}" (origk = pre-merge cluster count read
                                        from the pre-merge model; k = the merged model's own cluster count),
                                        replacing any stage1/stage2 wording entirely
            {f}       - frequency value with '.' replaced by '_' in filenames, e.g. 300.00 Hz -> 300_00
            [cond]        - only created when individual_frequencies_cluster_assignment_plots = True
            [html cond]   - only created when generate_interactive_html_plots = True
            [no-bl cond]  - only created when baseline_data_separation = False
            [bl cond]     - only created when baseline_data_separation = True
            [k>1 only]    - the whole {klabel}/ directory and everything inside it is only created when
                            the resolved model's own k > 1 (k=1 is skipped entirely, no directory made)

[4] Assumptions and Constraints
=================================================================================================================
    - Assumptions

        (1) The first file listed in the "directory_path" of the "file_list_config.cfg" is assumed to be correct and used as reference file in the "tsb_frf_clustering_inference_application".
        (2) "END" string should be present at the end of data files.
        (3) First 9 rows in the data files have no frequency, gain and phase values / information.
        (4) The length of the frequencies and the individual frequencies must be exactly same throughout the data files.
        (5) The data filenames must follow the nomenclature "<drive_name>_<head>_<cylinder>_<temperature>_<use_case>".

    - Constraints

        (1) The config files are to be stored in the config directory within the application packages.
        (2) The tool relies on "Plotly" and "Matplotlib" to generate visualizations, which may be slow for very large datasets.
        (3) When in the config, "individual_frequencies_cluster_assignment_plots = True", the application will take longer to run as "2D cluster assignment plots" and "2D fan segment plots" for each frequency is generated separately.
        (4) Performance may degrade with very large numbers of files.
        (5) For a large number of files (>100000), interactive 3D visualization will use large amount of disk space and maybe slow to load.
        (6) For a larger number of files (>200000), interactive 3D visualization may not be created.
        (7) In "input_inference_config.cfg", only the "INFERENCE_APPLICATION_REQUIRED_PARAMETER" should be updated as per requirements and the "TRAINING_APPLICATION_SPECIFICATIONS" should be unchanged as they are the specifications generated directly as a result of the training application. If "TRAINING_APPLICATION_SPECIFICATIONS" are changed, then "tsb_frf_clustering_inference_application" will behave unexpectedly.
        (8) The individual frequency values for data files used in "tsb_frf_clustering_inference_application" should be the same as the individual frequency values of the data files used in "tsb_frf_clustering_training_application".
        (9) Microsoft Excel cannot open CSV files if the full file path exceeds 259 characters due to Excel's path length limitation in Windows 11 Pro.
        (10) To represent pre and post merge cluster counts, output file names have been updated to contain both "k" values. The original k is represented as "orig<k>" and the merged k is represented after the as "orig<k>_k<merged_k>".
        (11) The nomenclature of the output files are updated to shorter names for easier path handling. In place, several abbreviations are used as below:
            -------------------------------------
            | Label               | Abbreviation|
            -------------------------------------
            | centroid            | cen         |
            | stage1              | s1          |
            | stage2              | s2          |
            | bode                | b           |
            | drive               | d           |
            | cluster(s)/clustered| c           |
            | frequency           | f           |
            | gain                | g           |
            | phase               | p           |
            | original            | orig/o      |
            | interactive         | int         |
            | trajectories        | traj        |
            | hierarchical        | h           |
            -------------------------------------

[5] Revision
=================================================================================================================

2026/01/16 - v001 Release
    - Release of the FRF Clustering Inference Application.
    - Supports the following functionalities: input handling, summary csv creation, clustering inferencing results, metric comparisons and static and interactive EDA plots.

2026/02/13 - v002 Release
    - Includes the following modifications:
        a. New parameters "root_dir" and "output_path" added in the configuration file.
        b. "root_dir" is used to set the path to the analysis folder generated from "tsb_frf_clustering_training_application" that contains the trained models.
        c. "output_path" is used to set the path where the output directory will be generated.

2026/05/29 - v003 Release
    - Includes the following modifications:
        a. New clustering approach "Hierarchical Clustering" added to the inference application, which takes a two stage approach for clustering FRF data.
        b. New preprocessing step called "Meanline Data Separation" added to the inference application, which is a preprocessing step for segregating the data files into phase lead and phase lag and perform clustering on them individually.
        c. 6 new features relating to second derivation, peak prominence and moving averages added to the training application.
        d. Bode plot centroid only visualization updated to include total file counts for a respective cluster in the legend.
        e. Gain Phase vs Frequency plot updated for higher resolution.
        f. Dynamic understanding of the specification used for training application for exact inference application execution.

2026/09/24 - v004 Release
    - Includes the following modifications:
        a. Preprocessing is updated from standard scaler (mean and standard deviation) to normalization from [-1, 1] + detrending.
        b. "Meanline Data Separation" is updated to "Baseline Data Separation", which is a preprocessing step for segregating the data files into phase lead, phase lag and no resonance sub-groups.
        c. 2 new data related visualizations added, these include: Segment Normalized and Detrended Plot (representation of segment data pre and post preprocessing) and Baseline Group Separation Plot(segment data post baseline data separation).
        d. 1 new centroid related visualization added, namely: Bode Centroid Metrics (1x4 grid, showing centroids raw -> normalized -> raw detrend lines -> normalization + detrended).
        e. 3 new centroid related metrics are added, these are: Correlation, RMSE and Wasserstein.
        f. Nomenclature updated to include abbreviations instead of labels.
        g. Bode plot centroid only visualization updated to include measured data file counts and worst model data file counts for a respective cluster in the legend.
        h. Inference Application to run purely on single stage clustering models.
